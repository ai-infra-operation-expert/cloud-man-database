# AI Stack 竞品对比矩阵

> **目的**:给 AI Stack 团队一个客观、可决策的对照表,识别差异化方向。
> **用法**:已知事实标 ✅/⚠️/❌,待你 / 团队实际验证的标 `__需验证__`。
> **更新周期**:每季度复盘一次,产品/客户现场变化都要回填。

## 0. 对标对象(选这 4 个,理由在末尾)

| 项目 | 为什么选它 | 威胁等级 |
|---|---|---|
| **GPUStack** | 跟 AI Stack 定位最像(多硬件 + 集群),开源里最易上手,文档好 | ⭐⭐⭐ 高 |
| **Xinference** | 国产 + 多模态齐 + supervisor-worker 架构,跟你们客户群重合 | ⭐⭐⭐ 高 |
| **AIBrix**(字节) | K8s 原生 + vLLM 深度集成,思路最接近"ACK + AI Stack" | ⭐⭐ 中-高 |
| **BentoML / OpenLLM** | 偏 serving 框架,代表"海外/学术派"思路 | ⭐ 低-中 |

> **不选** llm-d(太新、生产案例少)、Ollama/LM Studio(单机不算集群)、Dify(应用层不对标)。

## 2. 差异化结论(待你 review)

> 草拟,基于公开信息。**未经你/团队现场验证。**

### 我们的护城河(3 条候选)

1. **异构国产卡深度支持**(华为昇腾 / 摩尔线程 / 海光 DCU)— 客户私有机房刚需,开源项目大多偏 NVIDIA
2. **ACK 原生 + 工单/SRE 体系** — GPUStack/Xinference 都是"独立产品",跟客户现有 K8s/工单系统脱节,我们是 ACK 一部分
3. **国内合规 + 阿里云监控集成** — 自研护城河,开源方案都要自己接 ARMS/SLS

### 我们的短板(3 个)

1. **多模态生态** — Xinference 早把 ASR/TTS/Embedding/Rerank 打包,我们要补
2. **国际开源影响力** — 字节/Seal 有海外社区,我们基本只服务阿里云客户
3. **产品易用性** — GPUStack 一键装,我们大概率要写一堆 YAML

### 建议打的差异化(给 manager 看的一句话)

> "AI Stack = **ACK 原生 + 国产异构卡 + 工单/SRE 闭环**;开源对标的是 **多硬件集群管理能力**,我们卖的是 **'装得起来 + 跑得稳 + 出问题有人管'** 的端到端 SLA。"

## 附:为什么是这 4 个对标

- **GPUStack** = "Seal 软件出的 LLM 版 Rancher",UI/UX 直接对标
- **Xinference** = "国内对标 GPUStack",客户常拿来问"为啥不用这个"
- **AIBrix** = "字节版 vLLM-on-K8s",思路对 ACK + AI Stack 有参考价值
- **BentoML** = "海外/学术派代表",看趋势

**没选**:
- llm-d(Red Hat,太新,生产案例少)
- Ollama / LM Studio(单机不算集群)
- Dify / FastGPT(应用层,不是基础设施)
- vLLM / TGI / SGLang(它们是 worker,不是 manager — GPUStack 调的就是这些)
